What is Cypress?

· Cypress is a next generation front end Automation testing tool built for the modern web applications

How Cypress is Unique from other Automation tools?

Cypress automatically waits for commands and assertions before moving on. No more async hell.

Ability to test Edge Testcases by Mocking the server response

Cypress takes snapshots as your tests run. We can hover over each commands in the Command Log to see exactly what happened at each step.

Because of its Architectural design, Cypress delivers fast, consistent and reliable test execution compared to other Automation tools

View videos of your entire tests execution when run from the Cypress Dashboard.

Cypress built on Node.js and comes packaged as an npm module,

As it is built on Node.js, It uses JavaScript for writing tests. But 90% of coding can be done using Cypress inbuilt commands which are easy to understand.

Cypress also bundles with jQuery and inherits many of jQuery methods for UI components Identification

Cypress Architecture

Most testing tools (like Selenium) operate by running outside of the browser and executing remote commands across the network. But Cypress engine directly operates inside the browser. In other words, It is the browser that is executing your test code

This enables Cypress to listen and modify the browser behavior at run time by manipulating DOM and altering Network requests and responses on the fly

Cypress open doors to New Kind of testing with Having ultimate control over your application (front and back)

Summary: Page Transitions in Cypress

Cypress automatically handles page transitions during a test, such as navigating from one page to another using cy.visit() or a .click() that loads a new page. When a page transition is detected, 
Cypress pauses test execution until the new page has fully loaded.

This built-in behavior prevents:

Running commands on a stale (old) page

Interacting with a partially loaded page

Normally, Cypress waits up to 4 seconds to find DOM elements. However, when a page load event is detected, 
Cypress automatically increases the timeout to 60 seconds for that specific event. If the page fails to load within this time, 
the test fails with an error.

Overall, Cypress dynamically adjusts timeouts based on application behavior, reducing the need for manual waits.
 These timeout values can be configured in Cypress settings.

Multiple ways to select locator in css

1. by data attribute
<button data-cy="submit-btn">Submit</button>
cy.get('[data-cy="submit-btn"]')

2. by id 
<input id="email" />
cy.get('#email')

3. by class
<div class="login-button"></div>
cy.get('.login-button')

4. by tag name
cy.get('button')

5. by Attribute selector
<input type="text" name="username" />
cy.get('input[name="username"]')
cy.get('input[type="text"]')

6. By Multiple attribute combination
cy.get('input[name="username"][type="text"]')

7. By Parent → Child relationship
cy.get('.login-form > input')
cy.get('.login-form').find('input')

8. By Index (nth-child)
cy.get('ul li:nth-child(2)')

9. 
By Text content (Cypress-specific)
cy.contains('Submit')

or with selector:
cy.contains('button', 'Submit')

10.By Traversal methods
cy.get('.item').first()
cy.get('.item').last()
cy.get('.item').eq(2)

11. By Form-specific selectors
cy.get('input:checked')
cy.get('input:disabled')
cy.get('input:visible')

12. Using aliases
cy.get('[data-cy="submit-btn"]').as('submit')
cy.get('@submit').click()

how cypress auto handle alert in web apps
Types of alerts Cypress handles
window.alert() cy.get('#alert-btn').click()
window.confirm() cy.get('#confirm-btn').click()
window.prompt() Cypress does not support prompt inputs directly.

validation:
cy.on('window:alert', (text) => {
  expect(text).to.equal('Are you sure?')
})

cy.on('window:confirm', (text) => {
  expect(text).to.contain('Do you want to proceed?')
})

cancel modal ; cy.on('window:confirm', () => false)
Handling window.prompt()

Stub the prompt before triggering it:

cy.window().then((win) => {
  cy.stub(win, 'prompt').returns('Cypress Input')
})

cy.get('#prompt-btn').click()

Why Cypress can’t handle child tabs directly

Cypress runs in a single browser tab

New tabs opened using:

window.open()

<a target="_blank">

Cypress blocks new tabs by design

approach 1: 
cy.get('a[target="_blank"]')
  .invoke('removeAttr', 'target')
  .click()

approach 2: 
cy.window().then((win) => {
  cy.stub(win, 'open').as('windowOpen')
})

cy.get('#openTabBtn').click()

cy.get('@windowOpen')
  .should('be.calledWith', 'https://example.com')

approach 3
Visit the Child Tab URL Manually

Extract the URL and navigate directly:

cy.get('a[target="_blank"]')
  .then((el) => {
    const url = el.prop('href')
    cy.visit(url)
  })


Approach 4: Validate Only the Link (No Navigation)

When navigation is not required:

cy.get('a[target="_blank"]')
  .should('have.attr', 'href')
  .and('include', 'docs')
